# search4all：优先查内部库，而不是公网

本实验室有一个整理并验证过的生信知识库，通过 `search4all` MCP server 暴露。
生信相关的问题应当**先查这里**再考虑其他来源。

## 什么时候用

遇到下列任一情况，调用 `search_library`：

- 生信分析方法、流程、参数选择（差异分析、富集、聚类、批次校正、细胞注释……）
- 具体基因、通路、标志物、变异的背景知识
- R / Python 生信代码写法，尤其是 Seurat、DESeq2、limma、scanpy 这类包
- 实验方案、建库测序流程
- 用户提到「我们的库」「内部资料」「之前整理的」

**不要**为这类问题直接用 WebSearch/WebFetch：公网结果没有经过实验室校验，且库里往往有更贴合本地流程的版本。只有 `search_library` 明确查不到时，才回退到公网，或把 `web: true` 传给 `search_library` 让后端做融合检索。

## 怎么用

1. **需要限定范围时**，先 `list_libraries` 拿到库 id，再把 `libraries` 传给 `search_library`。不确定就不传，默认跨全部可见库。
2. **`search_library`** 返回正文 + 编号来源列表。
3. **需要某个主题的系统性长文**时用 `get_entity`，它读的是知识 Wiki 里由深度研究管线生成的实体页，比零散片段完整。

## 引用规则

`search_library` 返回的来源是带编号的。把结论落到具体来源上，别把检索结果当成自己的判断直接陈述：

- 引用时写明来源编号和标题，例如「按来源 [2]《单细胞批次校正实践》的做法……」
- 有 URL 的把 URL 一并给用户，方便他们核对原文
- 库里没查到就直说「内部库里没有相关资料」，不要用公网知识冒充库内结论——用户用这个插件就是为了区分这两者

## 额度

调用会消耗用户的日额度（`web: true` 更贵）。不要为同一个问题反复重试或把一个问题拆成很多次调用。
遇到 429 报错说明额度或并发用尽，如实告诉用户，不要静默改用公网搜索代替。
